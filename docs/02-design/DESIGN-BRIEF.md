# DESIGN BRIEF — TicketChile

## 1. Objetivo visual
Rediseñar TicketChile desde cero con un lenguaje contemporáneo de entretenimiento/eventos premium, manteniendo identidad dark + rojo pero elevándola.

Debe sentirse:
- profesional
- cultural
- enérgica
- premium
- audiovisual
- confiable
- humana
- chilena sin clichés

No debe sentirse:
- template SaaS
- dashboard de fintech genérico
- clon de Netflix
- web de casino
- “generado por IA”
- cyberpunk innecesario

## 2. Referencias compartidas
### Referencia A — panel cinematográfico con marco redondeado
Tomar:
- fondo expandido derivado del contenido
- shell central contenido
- borde fino
- profundidad
- navegación minimal
- jerarquía hero + rail

Adaptar:
- poster rail → eventos
- movie metadata → fecha/lugar/precio
- watch CTA → comprar/ver entradas

No copiar branding ni composición 1:1.

### Referencia B — ticketing/cinema
Tomar:
- negro profundo
- rojo como acento
- poster a la izquierda
- contenido/transacción a la derecha
- ticket como objeto visual
- stepper sobrio

Adaptar al checkout y detalle de evento.

### Referencia C — hero inmersivo
Tomar:
- imagen dominante
- panel translúcido/oscuro sobre fondo
- carrusel horizontal
- navegación delgada
- sensación audiovisual

No usar el morado de referencia. TicketChile mantiene rojo como acento primario.

## 3. Tres rutas que Claude Design debe proponer
### V1 — CINEMATIC EDITORIAL
- fotografía protagonista
- mucho negro
- tipografía editorial
- layouts amplios
- cards de imagen
- transiciones sofisticadas

### V2 — LIVE CULTURE
- mayor energía
- tipografía condensada para headings
- ticket strips
- módulos asimétricos controlados
- acentos gráficos inspirados en pulseras/tickets/eventos

### V3 — PRECISION PREMIUM
- más sobria
- minimal high-end
- grid preciso
- menos efectos
- datos y compra muy claros
- ideal para confianza transaccional

Las 3 deben verse como la misma marca TicketChile, no como tres empresas distintas.

## 4. Color
Base propuesta:
- Background 0: casi negro
- Background 1: carbón
- Surface: negro/gris elevado
- Text primary: blanco cálido
- Text secondary: gris claro
- Accent: rojo TicketChile
- Success/warning/error semánticos separados

No usar gradientes azul/morado SaaS como lenguaje base.

## 5. Tipografía
Usar máximo 2 familias:
- Display/headings con personalidad controlada.
- Sans legible para interfaz.

Necesitamos:
- headings editoriales
- números/tablas muy legibles
- CLP alineable
- acentos y español completos

## 6. Radii
Evitar “todo redondeado”.
Definir 3 niveles:
- small: inputs/chips
- medium: cards
- large: hero/shell

El hero puede usar radio más expresivo; tablas y superficies operativas deben ser más contenidas.

## 7. Cards
Event card:
- imagen dominante
- título
- fecha
- ciudad
- desde $
- status/tag mínimo

No poner cada dato dentro de una píldora.

## 8. Dashboards
Evitar mosaico de 12 KPI cards iguales.
Preferir:
- 2–4 métricas prioritarias
- un gráfico principal
- alertas accionables
- lista de eventos
- tareas
- side panel contextual

## 9. Mobile
Diseñar mobile al mismo nivel que desktop.
No es una adaptación posterior.

Obligatorio:
- 390px y 430px
- navegación mobile
- sticky purchase CTA cuando corresponda
- filtros en sheet
- tablas convertidas a lista/cards
- bottom sheets para acciones
- formularios con teclado y safe-area considerados

## 10. Motion
- contenido entra por jerarquía, no todos a la vez
- hover limitado
- transitions 180–350ms
- hero transitions 400–700ms máximo
- reduced motion
- evitar efectos que reduzcan legibilidad
